# SSH 服务器工具 / Named SSH

DeepSeek Harness 的独立 SSH 工具插件。**你在设置页填写、测试并保存凭据，Agent 只使用服务器别名，不需要知道密码。** 不替换本地 Bash、文件系统或工作区。

## 使用

1. 安装并启用插件后，打开 **设置 → SSH 服务器**。
2. 添加别名（例如 `dev-box`）、地址、端口、用户名和远程默认目录。支持密码，或粘贴 PEM/OpenSSH 私钥及可选口令。
3. 点击获取指纹。**通过服务器控制台或管理员提供的渠道独立核对 SHA256 主机指纹**，然后勾选确认。网络上获取的指纹本身不证明服务器身份。
4. 点击 **测试并保存**。只有指纹匹配且登录成功才保存；勾选允许 Agent 访问后，该别名对当前 profile 的 Agent 可用。
5. 对 Agent 说：`请在 dev-box 上查看磁盘空间。` Agent 用 `ssh_list_servers` 发现别名，再调用 `ssh_exec`。每次远程命令经过 Harness 执行确认，不需要再输入 SSH 密码。

主机指纹改变时连接会被拒绝，必须由你重新核对并重新提供凭据；Agent 没有信任新主机、保存密码或启用服务器的工具。

## 工具

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `ssh_list_servers` | 无 | 列出允许 Agent 访问的别名及非秘密连接信息 |
| `ssh_test_connection` | `alias` | 用后台凭据与已固定指纹测试登录，不执行命令 |
| `ssh_exec` | `alias`, `command`, 可选 `cwd`, `timeout_ms` | 经用户执行确认后运行非交互远程命令，返回 stdout、stderr、退出状态 |

命令默认 30 秒，范围 1–120 秒。stdout/stderr 各最多 64 KiB，超出返回 `truncated: true`，不生成含原始输出的日志文件。每次调用创建独立 SSH 连接和 shell，`cd`、环境变量不会保留到下次；用 `cwd` 指定目录。最多同时 4 个连接。不提供交互 PTY、跳板链、SSH agent 转发、自动重试或专用 SFTP 工具；远程文件操作可通过明确的 shell 命令完成。

## 凭据与安全边界

- 凭据仅经用户设置页发送到 Harness Host，由 `ctx.credentials` 的插件专属记录保管。**不放入插件配置、模型工具 schema/参数、提示词、会话消息、远端 shell 命令、环境变量、stdin 或进程命令行。**
- 列表、保存结果和编辑表单均不回填秘密；错误只返回固定错误代码/文字，不转发 SSH 库的原始错误。输出对本次使用的凭据做字面脱敏，这只是额外防护，不是通用 DLP。
- 当前 Harness 使用本地文件凭据提供者：凭据保存在其受限权限文件中，**不是系统钥匙串，也不是加密保险箱，更不是针对同一操作系统用户的强隔离**。具有本机读取/执行权限的 Agent 仍可能主动读取。此限制符合用户最终选择的“正常不进入模型上下文”，不宣称抵御恶意 Agent。
- 保存凭据是授权行为，只有已认证的 owner 配置接口提供；没有相应 Agent 工具。与用户同等本机/浏览器权限的程序仍可能调用管理接口。
- 原始命令输出会进入模型上下文；远端业务文件可能另含其他秘密。请使用低权限专用账户，别把本地凭据文件共享到远端，别要求 Agent 输出秘密。远程权限不受本地文件沙箱约束。
- 超时/取消会关闭 SSH 通道，但不能保证远端子进程已经终止。变更命令失败后，应先检查远端状态，不要直接重试。
- 用户保存时的连接测试只验证 SSH 登录；不校验目录一定存在。命令执行会明确返回目录错误。
- 配置修改按 revision 拒绝陈旧覆盖，凭据在每次操作重新读取。正在执行的连接可能仍用旧凭据；删除/禁用影响后续操作，不撤销已经发出的命令。
- 修改地址、端口、用户名、认证方式或指纹时，不能静默复用旧凭据，需重新输入。

## 安装与开发

在 Harness 插件管理器中安装此目录，或让 Agent 使用 `plugin_manager install_bundle`；不要手工改 profile 配置。安装改变当前 profile 的所有会话。运行环境：Node ≥22，目标 Harness 0.2.2-rc.1。

```sh
pnpm install --ignore-scripts
pnpm test
pnpm run check
```

依赖 `ssh2@1.17.0` 使用纯 JavaScript 路径，开发安装不运行依赖脚本。若插件管理器报告可选 native 构建待批准，可不批准、不执行；功能测试使用相同的无脚本安装。

- [核心实现](<core.js>)：验证、凭据记录、连接、指纹、执行与脱敏。
- [Host 插件](<index.js>)：工具、执行确认、认证管理接口。
- [设置页](<client.js>)：人工配置、独立指纹确认、测试保存。
- [测试](<test/core.test.js>)：本地临时 SSH 服务和假凭据，不访问你的服务器。

## 与 dsh-ssh 的区别

参考项目 [UynajGI/dsh-ssh](<https://github.com/UynajGI/dsh-ssh>) 主要把整个工作区的执行与文件能力切换到远端。本插件是独立的别名工具，保留本地能力，并采用 Harness 凭据服务、人工确认的主机指纹和保存前验证。实现为新编写代码，不复制该项目源码。
