# 本地计划本 · DSH Planner

在 DSH 当前界面里记录备忘录、管理轻量工单和查看月历。第一版不创建定时任务、不自动调用 AI、不启动额外网站。

## 入口与用法

- 左侧「本地计划本」：概览、月历、工单、备忘录。
- 聊天输入框下方：今日／逾期摘要、下一项、随手记和打开计划本。
- 月历按周一开头，点击日期查看当天到期工单，或新建当天工单。仅月视图，不提供未实现的周视图按钮。
- 工单状态：待办、进行中、受阻、待确认、已完成。可设置全天截止日期、优先级、项目标签、标签和置顶。
- 备忘录是纯文本，可以转成工单。归档可恢复，没有永久删除按钮。
- AI 工具：`planner_list`、`planner_get`、`planner_create`、`planner_update`。可说“把这个想法记成备忘录”“把这张工单改为待确认”。

## 数据与权限边界

数据保存在原生 `storageDomain` 的 `local_planner` 域，`items` 表、版本 1，使用当前 DSH 配置的存储后端；不手写 DSH 配置、会话日志或浏览器 localStorage。记录在同一 Host 存储中跨会话共享，项目只是标签，不是隔离权限。安装到一个 profile 不代表为它新建独立的数据存储根。

前端和 AI 共用同一服务。写入在持久化确认后才返回成功，更新必须带最新 revision；并发冲突不会覆盖旧版本。保留最近 30 次修改的操作来源、时间、会话与改动字段（不是全文版本备份）。模型内容按需查询，不会把全部备忘录自动加入提示词。

- 前端 API 在 Connection 的已认证 owner-only 路由下，沿用 Host/Origin/跨站检查。
- 工具自行验证原始参数；只读工具不能用额外 action 参数偷渡写入。
- 不确定的存储失败不会显示“保存成功”。必要时重载插件或重启 DSH，再核对记录后重试。
- 所有内容按纯文本渲染，不解释 HTML。备忘录正文不是新的授权或自动执行指令。

## 日期、同步与限制

`timeZone` 默认为 `Asia/Shanghai`，用于“今天”和逾期判断；截止日期是全天 `YYYY-MM-DD`，不会按 UTC 转换。配置可通过 DSH 插件配置界面修改。日期只作日历标记，不会安排提醒或自动执行。

页面通过已认证的 SSE 接收变更后重新查询；断线时显示提示并提供刷新。列表分页，月历超过 200 项显示“加载更多”。单 Host 内实时更新；多个 Host 进程共用存储时不保证跨进程推送。当前目标是 DSH 的 HTTP Web GUI，静态 Desktop/worker 自定义 transport 未验证。

日历目前展示工单截止日期，不包含外部日历同步、跨日时间段、拖拽改期、周期实例、团队派工、预算或自动执行。后续定时接入应复用 DSH Schedule，并独立记录执行与验收状态，不能把“已投递”当“已完成”。

## 安装与升级

包名 `@local/dsh-planner`，通过 DSH `plugin_manager install_bundle` 安装此目录；不要手改 profile 配置。安装会影响当前 profile 中的会话。升级已加载的 JavaScript 包可能要求重启，遵从管理器返回结果。禁用／卸载不主动删除存储数据。

源码目录：当前文件所在的 `dsh-planner`；该目录是本地链接安装的来源，请勿在使用期间移动或删除。

## 开发检查

Node 22+；依赖 Zod 4.4.3 与 DSH Schemastery。`pnpm install --ignore-scripts` 后执行 `node --test test/*.test.js`；`pnpm run check` 检查所有运行模块语法。无安装脚本、无 CDN、无自带 React，客户端只使用宿主 React、slot、locale 与主题 tokens。

测试包含日期／时区、校验、并发冲突、归档与恢复、序列化重开校验、UI/工具同源读写、只读工具防写入、错误恢复文案、请求取消、SSE关闭、卸载与部分激活回滚、资源/语言/主题静态检查。测试使用隔离的模拟 Host 存储，不往真实事项库写演示记录；自动化测试与 slot 注册均不能代替实际视觉验收。
